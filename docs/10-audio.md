# 10. 音(BGM) — HAMARU

2026-09-21 追加。v1.1 の「効果音・BGM(初期は OFF 既定)」(docs/00 §5)のうち **BGM** を実装する。
効果音(配置・消去の音)はまだ作らない。

## 1. 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 音源 | **持たない**。Web Audio API で合成する | mp3 を 1 曲入れると 300 KB〜。サイズ予算(docs/02 §9)を食い、PWA のキャッシュも重くなる |
| 既定 | **OFF** | docs/00 §5 の決定。いきなり音が出るのを嫌う人がいる |
| 鳴る場所 | 遊んでいる画面だけ(エンドレス / デイリー / レベル) | ホームや設定で鳴らす理由がない。画面を出た時点で止める |
| 切り替え | 設定「BGM」+ **ゲーム画面ヘッダの音符ボタン** | 既定 OFF のままでは誰も気づかないので、遊ぶ場所に 1 タップの入口を置く |
| 長さ | ループだが**毎回違う** | 32 小節(約 74 秒)で一巡する 4 つの展開。旋律は小節ごとに組み立てるので厳密な繰り返しにならない |

## 2. 曲(`src/audio/score.ts`。純粋)

- **ハ長調**、104 BPM、4/4。明るく、急かさないテンポ。
- 和音は 8 小節で I–vi–IV–V–I–vi–ii–V(C–Am–F–G–C–Am–Dm–G)。素直に気分が上がる進行。
- 旋律は**ペンタトニック**(ド レ ミ ソ ラ)。半音がないので、どの音が来ても和音とぶつからない。
  音域は C5〜E6 の 1.5 オクターブに絞る(耳に刺さらない)。
- 旋律は 8 小節をまとめて作り、前半は上り・後半は下りに寄せて**山なり**にする。
  小節ごとに独立に作ると音域が飛んで「でたらめ」に聞こえるため(§7 N-1)。
- 8 小節 × 4 周で展開が変わる。

| 周 | 旋律の密度 | シェイカー | 和音刻み |
|---|---|---|---|
| 1 | 0.7(静かに始まる) | なし | 裏拍(2・4) |
| 2 | 0.9 | あり | 裏拍 |
| 3 | 1.0(盛り上がり) | あり | 4 拍すべて |
| 4 | 0.8 | あり | 裏拍 |

音色(すべて発振器の合成):

| 声部 | 音 | 役割 |
|---|---|---|
| lead | 正弦波 + 3 倍音の短い減衰(鉄琴のような撥弦) | 旋律。付点 8 分のディレイで軽く響かせる |
| chord | 三角波を少しデチューン | 裏拍の刻み。跳ねる感じを作る |
| bass | 三角波 + 700 Hz ローパス | 主音 → 5 度 → 1 オクターブ上 |
| kick | 正弦波を 130 → 45 Hz へ | 1・3 拍 |
| shaker | 白色雑音 + 6.5 kHz ハイパス | 8 分の裏 |

`barNotes(bar)` は**通し小節番号だけで決まる**(同じ小節はいつも同じ)。だから途中から鳴らし始められるし、
和音から外れていないかを単体テストで確かめられる(`tests/unit/music.test.ts`)。

## 3. 再生(`src/audio/player.ts`)

- 25 ms ごとに「今から 0.3 秒先までに始まる小節」を予約する。**鳴らす時刻は AudioContext の時計**で、
  `setInterval` の揺れは音に出ない。予約は 1 回に 8 小節まで(タブ復帰で時計が飛んでも暴走しない)。
- ブラウザは操作前に音を出せない。`start()` は失敗せず、次の `pointerdown` で `resume()` を試す。
  止まっていた間は時計を進めない(無音の小節を飛ばさない)。
- タブが隠れたら `suspend()`、戻ったら再開する(電池とバッテリ)。
- 出口は 音量 → 6 kHz ローパス → スピーカー。開始は 0.8 秒でフェードイン、停止は 0.35 秒でフェードアウト。
- ON にするまで **AudioContext を作らない**。OFF のままなら音まわりのコストはゼロ。

## 4. 画面と設定

- 設定「BGM」(`settings.music`、既定 false)。docs/01 §10 の `settings` に 1 項目追加。
- ゲーム画面ヘッダ(戻るの隣)に音符ボタン。ON のときは金継ぎ色 + 斜線なし、OFF は斜線つき。
  `aria-pressed` を持つトグルボタンで、ラベルは「BGM を鳴らす / 止める」。
- 画面を出る(`unmount`)と必ず止めて AudioContext を閉じる。

## 5. config(docs/02 §4.1)

```jsonc
"audio": { "bpm": 104, "volume": 0.32 }
```
`bpm` は 60〜160、`volume` は 0〜0.6(zod で範囲を強制)。**実験のオーバーライドには入れない**
(`configOverrideSchema` に audio を足していない)。音量を実験で変える価値より事故の方が大きい。

## 6. 予算と確認

- 追加した JS は gzip で 2.8 KB(29.06 → 31.82 KB。音源ファイルは 0 バイト)。初回 JS の予算 60 KB(docs/02 §9)に対して十分小さい。
- CPU: 1 小節あたりの発振器は 30 個前後、どれも 1 秒以内に終わる。
- **耳で確かめる**: `npm run audio:preview -- --out /tmp/hamaru-bgm.wav`
  (曲は本番と同じ `score.ts`、音色は Node 上の簡略版。歪んでいないか peak も出る)。
- 単体テスト: 決定性・音がハ長調から外れないこと・旋律が跳びすぎないこと・予約の先読み。

## 7. 実装ノート

### N-1. 旋律は 1 周まとめて作る(§2)
最初は小節ごとに独立に作っていたが、小節の頭で音域が 2 オクターブ飛び、「でたらめに聞こえる」状態だった
(C6 → E7 → A5 → D7)。8 小節ぶんを続けて歩かせ、前半上り・後半下りの山なりにした。
`barNotes` は直前の 1 周ぶんを覚えておくだけで、結果は小節番号だけで決まる(決定性は保つ)。

### N-2. 和音の基準音は 12 の倍数(§2)
和音の刻みを「55 + 構成音」で書いたら曲全体が完全 5 度上にずれ、進行が C→G、Dm→Am になっていた
(F# が出て調も外れた)。基準は C3 = 48。単体テスト「どの音もハ長調から外れない」がこれを止める。

### N-3. 音量は volume だけで決める(§5)
声部ごとの gain は 0〜0.5 で、同じ拍に重なると合計 1.6 になることがある。実際の音量は master の
`volume`(既定 0.32)を掛けたもので、`audio:preview` の peak は 0.31(歪みなし)。
テストは「合計が 2 を超えない」= 指定を一桁間違えたときの網として置いている。
