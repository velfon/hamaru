# 01. ゲーム仕様書 — HAMARU

実装者向け。ここに書かれていない挙動は「もっとも単純な解釈」を採り、`docs/` に追記する。
数値はすべて `src/config/game-config.json` の**既定値**であり、改善ループが変更しうる。
ここでは `config.xxx` の形で参照する。

## 1. ルール(10 秒で説明できる形)

1. 盤は 10×10。手に持てるかけらは **1 個だけ**。
2. かけらをドラッグして盤の空きに置く。回転はできない。
3. 縦か横の 1 列(10 マス)が埋まると消える。複数列同時なら高得点。
4. **次のかけらは、いま置いた場所のまわりの盤の形がそのまま出てくる。**
5. 列を消さずにいると「熱」が上がり、出てくるかけらが**1 マスずつ大きくなる**。消すと 1 マスに戻る。
6. 置ける場所が無くなったら終了。

### この作りの狙い(逆手 — さかて)

普通のはめ込みパズルは「降ってくる運」と戦う。HAMARU は逆で、**次に来るものを作っているのは
プレイヤー自身**である。盤を散らかせば散らかった形が返ってくる。きれいに詰めれば素直な形が返る。
そして熱があるので「置きやすい形をただ並べ続ける」ことはできず、どこかで消しに行かされる。

**乱数を使うのは開始時の盤を作るときだけ**で、以後の供給に運は一切ない(§4)。
同じ盤から同じ手を打てば必ず同じ展開になる。つまり負けは全部自分のせいで、
「さっきのあの 1 手が悪かった」と分かる。これが「もう 1 回」を押させる。

## 2. 盤と座標

- 盤: `Board` = 長さ 100 の `Uint8Array`。`board[y * 10 + x]`、`0` = 空、`1..6` = 色インデックス。
- 座標: 左上が `(0,0)`、右方向 `x+`、下方向 `y+`。
- 盤サイズは `config.board.size`(既定 10)。**v1 の UI は 10 固定**だが、core は N×N に対応させる(将来の 8×8 モード用)。

## 3. かけら

形状カタログは**無い**。かけらは盤から導かれる任意の形で、`Piece` は
**正規化された相対座標の配列 + 色**だけを持つ。

```ts
interface Piece { cells: ReadonlyArray<[number, number]>; color: 1|2|3|4|5|6 }
```

正規化 = 左上を `(0,0)` に寄せ(`min(dx) === 0` かつ `min(dy) === 0`)、読み順(上から下、
左から右)に並べる。配置 API はこの**バウンディングボックスの左上**を `(x, y)` として扱う。
道具は `src/core/piece.ts`:

| 関数 | すること |
|---|---|
| `normalize(cells)` | 左上寄せ + 読み順に整列 |
| `largestGroup(cells)` | 4 近傍で最大のひとまとまり(同数なら読み順で先) |
| `resize(cells, n)` | ちょうど `n` マスにそろえる。足りなければ**読み順で最初の隣接マス**を足し、多ければ先頭から幅優先で `n` マス残す。**どちらもつながりを保ち、決定的** |
| `pieceSize(piece)` | 幅と高さ |
| `pieceCellsAt(piece, x, y)` | 盤上の絶対座標 |

かけらは必ず **1 つながり**で、大きさは 1〜`config.sakate.maxPiece`(既定 5)マス。

### 色
色は形ではなく**手数**から決まる(`colorFor(moves) = (moves mod 6) + 1`)。
乱数を使わないので再生検証と一致する。色の実値は [03-design-system.md](03-design-system.md)。

## 4. 乱数(使うのは開始時だけ)

### 4.1 乱数
- `createRng(seed: string)`: 文字列を `cyrb53` でハッシュし、`mulberry32` を初期化。
- エンドレスのシード: `endless:<installId>:<startedAtMs>`。
- デイリーのシード: `daily:<YYYY-MM-DD>`(**UTC** 日付。全世界共通)。

### 4.2 開始時の盤 `startBoard(config, seed)`
空盤に `config.sakate.startTiles`(既定 6)マスだけタイルを散らす。位置は乱数、色は順番。
**ここが乱数の唯一の使用箇所**であり、`GameState` は rng の状態を持たない
(以後の展開は盤と手だけで決まるため、途中再開しても列がずれない)。

最初の手持ちは常に **1 マス**(`seedPiece()`)。どこにでも置けるので初手で詰むことはない。

デイリーはシードが日付だけで決まり、盤の状態にも設定にも依存しない。したがって
**全プレイヤーの展開が完全に一致**する。これは公平性の要件で、実験でも変更不可
(`experiments.json` の `lockedInDaily` で保護)。

## 5. 配置・消去・次のかけら

### 5.1 配置可否 `canPlace(board, size, piece, x, y)`
かけらの全セル `(x+dx, y+dy)` が盤内かつ空なら true。

### 5.2 配置 `place(state, config, x, y) → { state, result }`
1. `canPlace` が false なら `result.ok = false`、state は不変。
2. セルを埋める(色はかけらの色)。
3. **完全に埋まった行・列を同時に検出**して全て消す(行と列の交差セルは 1 回だけ消える)。
4. スコア加算(§6)。
5. **熱を更新**: 1 列以上消えたら `heat = 0`、消えなければ `heat += 1`。`moves += 1`。
6. **次のかけらを作る**(§5.3)。渡す盤は**消去が終わった後**の盤。
7. **ゲームオーバー判定**: 次のかけらが盤のどこにも置けなければ `status = "over"`。
   レベルでは手数切れでも終わる(docs/09)。
8. `result` に `placedCells`, `clearedRows`, `clearedCols`, `clearedCells`, `scoreDelta`,
   `streakAfter`, `boardCleared`, `heatAfter`, `nextPiece`, `gameOver` を入れる(演出用)。

### 5.3 次のかけら `deriveNextPiece(board, size, placed, heat, cfg, moves)`

**逆手の心臓部。乱数ゼロ。**

1. いま置いたセルの**中心**を出す(各座標の平均を四捨五入)。
2. そこを中心とする `config.sakate.window`×`window`(既定 3×3)の窓を見て、
   **タイルのあるマス**を集める。**いま置いたマスは含めない**
   (含めると自分の形がそのまま返ってきて、盤の情報が入らないため)。
3. そのうち**いちばん大きなひとまとまり**を取る。ひとつも無ければ 1 マス。
4. `resize()` で**熱から決まる大きさ**にそろえる:

   ```
   pieceSizeFor(heat) = clamp(1 + floor(heat / config.sakate.growEvery), 1, config.sakate.maxPiece)
   ```

   既定は `growEvery = 2`, `maxPiece = 5` なので、熱 0–1 → 1 マス、2–3 → 2 マス、…、8 以上 → 5 マス。

3 までが「触れた形を窯が覚えている」、4 が「消さずにいると重くなる」。
**消すと窓が空くので次のかけらは小さく素直になる**——消去がそのまま次の手の楽さになる。

### 5.4 不変条件(テストで担保)
- 消去後に完全な行・列は存在しない。
- スコアは単調非減少。
- `place` は入力を変更しない(構造共有した新オブジェクトを返す)。
- 次のかけらは必ず 1 つながりで、セル数はちょうど `pieceSizeFor(heatAfter)`。
- 同じ `(初期盤, 手の列)` からは必ず同じ最終状態になる(golden テスト / サーバ再生検証)。

## 6. スコアリング

| 要素 | 式(既定) | config キー |
|---|---|---|
| 配置 | +セル数 | `scoring.perCell` = 1 |
| 消去 | `n` 列同時消しで `10 × n × (n+1) / 2` → 1:10, 2:30, 3:60, 4:100, 5:150, 6:210 | `scoring.lineBase` = 10 |
| ストリーク | 連続して消去が発生した配置回数 `s`。消去点に `min(1 + step×(s−1), max)` を乗算 | `scoring.streak.step` = 0.25, `scoring.streak.max` = 2.0 |
| 全消し | 消去後に盤が空なら +300 | `scoring.boardClearBonus` = 300 |

- ストリークは「消去がない配置」で 0 に戻る(熱が 0 に戻る手と一致する)。
- 端数は各加算ごとに `Math.round`。
- 表示は 3 桁区切り。

## 7. モード

### 7.1 エンドレス(`mode: "endless"`)
- いつでも開始。終了時にベストスコアを更新。
- 途中終了(ホームに戻る)しても状態を保存し、次回「続きから」を出す。

### 7.2 デイリー(`mode: "daily"`)
- 1 日 1 題(UTC)。ホームのカードに「今日の挑戦」「残り時間」「達成状況」を表示。
- **何度でも挑戦でき、その日のベストが記録になる**(2026-09-21、docs/08 §1)。終了後は「もう一度挑戦」できる。
  ランキングに載るのもベスト。低い得点で終えても記録は下がらず、挑戦回数だけが増える。
- 途中再開可。ただし日付が変わったら破棄して新しい日に切り替える。
- 終了後の結果カード(§9.4)を共有できる。
- デイリー連続達成日数(`dailyStreak`)を保持。UTC で 1 日飛ぶと 0 に戻る。

### 7.3 将来(v1.1 候補、core は対応しておく)
- タイムアタック(`mode: "timed"`, 120 秒)、8×8 盤。

## 8. 操作

### 8.1 ポインタ(タッチ / マウス)
- 手持ちのかけらを `pointerdown` で掴む。**タッチ時は指の `config.input.touchLiftOffset`(既定 70 px)上**にかけらを持ち上げ、手持ちの表示サイズ(セル 0.7 倍)から盤のセルサイズへ 120 ms で拡大する。マウス時はオフセット 0。
- ドラッグ中、かけらの**左上セルに最も近い盤セル**をスナップ先とし、置けるなら「ゴースト」(半透明)を表示。さらに**置いた場合に消える行・列をハイライト**する(`config.input.previewClears`、既定 true)。
- `pointerup`: 置けるなら配置。置けないなら手持ちへ 180 ms で戻る。
- `pointercancel` / 画面離脱はキャンセル扱い。
- 盤外へのドロップはキャンセル。
- スクロールを防ぐため盤と手持ちに `touch-action: none`。

### 8.2 キーボード(アクセシビリティ要件)
- **選ぶ操作は無い**(手持ちは 1 個)。最初の矢印キーでカーソルが出て、以後は矢印で移動
  (かけらの左上基準)、`Enter`/`Space` で配置、`Esc` でカーソルを消す。
- カーソルが出ている間はゴースト表示。置けない位置では `aria-live` で「置けません」は言わない(うるさいため)。配置成功と消去は `aria-live="polite"` で「12 点、1 列消去」の形で通知。
- 手持ちは `aria-label` で「2×3、4 マスのかけら」、熱は「次は 3 マス」と読み上げる。

### 8.3 ハプティクス
- 配置成功で `navigator.vibrate(10)`、消去で `vibrate([10, 30, 20])`。設定で OFF 可(`settings.haptics`、既定 ON)。非対応環境では無視。

### 8.4 音(BGM・効果音)
- 遊んでいる画面(エンドレス / デイリー / レベル)でだけ鳴らす。**既定はどちらも OFF**(docs/00 §5)。
- 設定「BGM」(`settings.music`)と「効果音」(`settings.sfx`)で別々に、
  **ホームとゲーム画面の音符ボタン**で両方まとめて切り替えられる。
- 効果音が鳴るのは、置いた時・消えた時・全消し・レベルクリア・ゲームオーバー。
  連鎖が続くほど消える音が上がる。
- 音源ファイルは持たず、Web Audio で合成する。曲と実装は [10-audio.md](10-audio.md)。

ルーティングはハッシュ(`#/`, `#/play`, `#/daily`, `#/howto`, `#/settings`, `#/about`)。単一 HTML。

### 9.1 ホーム(`#/`)

```
┌──────────────────────────────┐
│ HAMARU               ♪  ⚙︎   │
│                              │
│ ┌──────────────────────────┐ │
│ │ 今日の挑戦  9/17         │ │  ← デイリーカード(未挑戦/挑戦中/達成 + 残り時間)
│ │ [ 挑戦する ]   連続 4 日  │ │
│ └──────────────────────────┘ │
│                              │
│ [ ▶ エンドレス ]  (続きから) │
│                              │
│ ベスト 12,340   プレイ 58 回 │
└──────────────────────────────┘
```
- 途中のゲームがあれば主ボタンは「続きから」、副に「はじめから」。

### 9.2 ゲーム(`#/play`, `#/daily`)
```
┌──────────────────────────────┐
│ ←   スコア 1,240   ベスト 9k │
│            ×1.5(ストリーク)  │
│ ┌──────────────────────────┐ │
│ │      10×10 盤            │ │
│ │  (画面幅いっぱい、正方形) │ │
│ └──────────────────────────┘ │
│                              │
│          ▣▣                  │  ← 手持ち(1 個。形は毎手変わる)
│          ▣                   │
│        次 ● ● ●              │  ← 熱(次のかけらの大きさ)
└──────────────────────────────┘
```
- 盤の一辺 = `min(画面幅 − 32px, 画面高 − ヘッダ − 手持ち, 520px)`。
- ストリーク倍率は 1.0 のとき非表示。
- 熱は数字ではなく**点の数**で出す(= 次に来るかけらのマス数)。消すと 1 点に戻る。
  「消さずにいると重くなる」ことを、読ませずに見せるための表示。
- 一時停止はない(状態は常時保存されるので、離脱=一時停止)。

### 9.3 ゲームオーバー(オーバーレイ)
- 置けないことが確定したら 600 ms かけて**置けないかけらを暗転**させてから表示。
- 内容: スコア、ベスト(更新時は「NEW BEST」)、消した列数、最長ストリーク、手数。
- ボタン: 「もう一度」(主)、「ホーム」。デイリーは「結果を共有」(主)、「ランキングを見る」、「もう一度挑戦」、「ホーム」。
  デイリーではその日のベストと挑戦回数(「今日のベスト 1,224(3 回目)」)も出す。

### 9.4 デイリー結果カード(共有テキスト)
```
HAMARU Daily #<n> (<YYYY-MM-DD>)
4,520 pts · 18 lines · streak x2.0
▓▓▓▓▓▓▓░░░
https://<host>/#/daily
```
- `#<n>` は 2026-10-01 を #1 とする通算番号(`config.daily.epoch`)。
- ゲージは `min(score / config.daily.shareGaugeMax, 1)` を 10 段階で表示(既定 6000)。
- `navigator.share` が使えれば共有シート、なければクリップボードにコピーし「コピーしました」をトースト表示。

### 9.5 設定(`#/settings`)
言語(自動 / 日本語 / English)、テーマ(自動 / ライト / ダーク)、ハプティクス、アニメーション軽減(OS 設定に従う / 常に軽減)、消去プレビュー、BGM、効果音、ランキングへの参加、データの削除(確認ダイアログ付き)、バージョン、「このゲームについて」へのリンク。

### 9.6 このゲームについて(`#/about`)
設定から開く 1 枚もののページ。節は 6 つで、順に
**About**(何のゲームか)/ **Modes**(4 つの遊び方)/ **Made**(作り: 広告なし・オフライン可・
デイリーの種・得点はサーバで再生して検証・音は合成)/ **Kaizen**(毎日の自動改善と公開リポジトリ)/
**Data**(何を送っているか。§11 と docs/04 §8)/ **Licence**(© lovenf.org・MIT・記録は本人のもの)。
末尾に著作権表示とアプリへ戻るリンク。

何を送信しているかは平易に明記する。「個人を特定する情報は送っていません」。
体裁は docs/03 §10 N-8(釉薬のチップ + 金継ぎの継ぎ目)。
この画面の文言は初回 JS に載せず、開いた時に読み込む(docs/02 §11 N-15)。

### 9.7 遊び方(`#/howto`)

逆手のルールは**読んで分かるものではない**ので、この画面は説明しない。**動かす**。

- 6×6 の小さな窯を 1 つ置き、プレイヤーが空きマスをタップして 1 手置く。
  すると窓のまわりにあった形が手に返ってくる。説明文は**いま起きたことを後から言うだけ**で、
  先回りしない(最初の 1 行は「空いているところをタップ」だけ)。
- 見本は `src/core` の `place` をそのまま呼ぶ。別実装を持たないので、ルールを変えたときに
  見本だけが古くなることが起きない。
- 熱は 1 から始める。熱 0 では返ってくるかけらが必ず 1 マスで、**肝心の「形が返る」が見えない**ため。
- 盤が 6×6 なのは、1 列(6 マス)そろうところまで数手で届くから。5×5 では熱の育ちに盤が
  追いつかず 3 手で詰んだ。最下段を 4 マス埋めておくと、**置く → 返る → 熱 → 消える**の
  一巡が最初の 4 手で出る。
- キーボードと読み上げには「おまかせで 1 手」を置く(タップと等価)。適当に置くと数手で
  詰んで何も学べないので、sim の greedy と同じ考え方で 1 手選ぶ。
  盤は `role="img"`(中身は装飾)、実況は `aria-live="polite"` の 1 行が担う。
- 最後に 1 文だけ、実演できないこと(運が無いこと)を書く。
- **いちばん最初の 1 回だけ**、ホームの「エンドレス / 今日の挑戦 / レベル」を押したときに
  自動で挟む(`howto:seen` が無く `stats.gamesPlayed === 0` のとき)。
  押した先は `?next=` で渡し、「はじめる」でそこへ戻る。以後はホームの「遊び方」から開く。
  **ルート(`#/play`)では挟まない**。ルートで挟むと、ブックマークや共有リンクで直接
  開いた人まで毎回そちらへ流れ、ゲーム画面そのものの表示速度も測れなくなる
  (docs/06 §9 N-11)。アプリは `/` から始まるので、実際にはほぼ全員がホームを通る。
- 画面も文言も初回 JS に載せず、開いた時に読み込む(docs/02 §11 N-15)。
  1 人 1 回しか通らない画面なので、常時読み込みに入れる価値がない。

## 10. 永続化(localStorage)

キー接頭辞 `hamaru:v1:`。全て JSON。`schemaVersion` を持ち、読み込み時に `migrate()` を通す。壊れていれば該当キーだけ初期化(ゲーム全体を止めない)。

| キー | 内容 |
|---|---|
| `install` | `{ id: uuid, createdAt, firstVersion }` |
| `settings` | §9.5 の設定 |
| `stats` | `{ gamesPlayed, bestScore, totalLines, totalScore, longestStreak, dailyStreak, lastDailyDate }` |
| `game:endless` | 途中の `GameState`(なければ削除) |
| `game:daily` | 途中の `GameState` + `date` |
| `daily:results` | 直近 60 日分 `{ date: { score, lines, attempts } }`(score はその日のベスト) |
| `telemetry:queue` | 未送信イベント |
| `experiments` | 割り当てキャッシュ `{ expId: variant }` |
| `howto:seen` | 遊び方を一度開いた印(§9.7)。初回だけ自動で挟むために使う |

localStorage が使えない環境(プライベートモード等)では**メモリ内フォールバック**で動作し、保存できない旨は出さない。

## 12. i18n

- `src/i18n/{ja,en}.json`。キーはドット区切り(`home.daily.title`)。
- 自動判定は `navigator.languages` の先頭が `ja*` なら ja、それ以外 en。
- 数値は `Intl.NumberFormat`、日付は `Intl.DateTimeFormat`。
- 文言の追加は両言語同時が必須(CI でキー差分を検査)。

## 13. エッジケースの仕様

| 状況 | 挙動 |
|---|---|
| 初手で置けない | 起きない。最初の手持ちは必ず 1 マスで、開始盤は最大でも `startTiles` マスしか埋まっていない |
| 行と列が同時に消え交差する | 交差セルは 1 回だけ数える。列数は行+列の合計(例 1 行 + 1 列 = 2 列 = 30 点) |
| 3×3 で 3 行 + 3 列同時 | 6 列 = 210 点 ×ストリーク |
| ドラッグ中にタブが非表示 | キャンセル。かけらは手持ちへ戻る |
| 日付が変わった瞬間にデイリーをプレイ中 | 進行中のゲームは続行できる。終了時の記録は**開始時の日付**に紐づける |
| localStorage の容量超過 | `telemetry:queue` を捨ててから再試行。それでも失敗なら黙って続行 |
| 画面回転 | 盤を再レイアウト。ドラッグ中ならキャンセル |
| 二本指 | 最初のポインタのみ扱う(`pointerId` 固定) |
| 置いたまわりにタイルが 1 つも無い | 窓が空なので次のかけらは 1 マス(を熱の大きさに `resize`) |
| 窓から拾った形が熱の大きさより大きい / 小さい | `resize()` でちょうどその大きさにする(§3)。つながりは保たれる |
| 熱が上限に達した | `maxPiece`(既定 5)で頭打ち。以後は消すまで 5 マスが出続ける |
| 全消し | 盤が空 → 窓も空なので次は 1 マス。仕切り直しになる |

## 14. 実装ノート(実装フェーズで解消した曖昧さ)

### N-1. 正規化 = バウンディングボックス原点寄せ(§3)
かけらは「左上が (0,0) に寄っている = `min(dx) === 0` かつ `min(dy) === 0`」を不変条件とし、
セルは読み順(y 昇順 → x 昇順)に並べる。配置 API(`canPlace(board, size, piece, x, y)`)は
(x, y) を**バウンディングボックスの左上**として扱う。§8.1 の「かけらの左上セル」もこの点を指す。
`normalize()` を通していない `cells` は core に入れない(`deserialize` も通す)。

### N-2. 色は手数から(§3「色」)
旧仕様は「形状カテゴリで色を固定」だったが、逆手には形状カテゴリが無い。
`colorFor(moves) = (moves mod 6) + 1` とし、盤は自然に 6 色が巡る。
色はゲーム性に影響しない(見分けのためだけ)ので、再生検証では照合しない。

### N-3. 窓は「置いたマスを除く」(§5.3)
置いたマスを含めると、次のかけらが**いま置いた形そのもの**になりやすく、
盤の情報が入らない(= 同じ形を延々と置き続けられる)。除くことで
「まわりに何があったか」だけが伝わり、盤を読む意味が生まれる。

### N-4. 熱がないと終わらない(§5.3 手順 4)
試作では熱なし(窓の形をそのまま使う)で 5,000 手打っても終わらなかった。
かけらが 1 マスに収束し、1 マスは常にどこかに置けるからである。
**熱**(消してからの手数で大きくなる)を足すと、消さない限り必ず詰む形になり、
ゲームが終わり、上手さが得点に出るようになった(ボット差 4.6 倍 → 実測 20 倍)。
`growEvery` と `maxPiece` がゲームの難度そのものなので、変更は sim で必ず確認する。

### N-5. 共有ゲージは切り捨て(§9.4)
§9.4 は「`min(score / shareGaugeMax, 1)` を 10 段階で表示」としか書いていないが、
同じ節の例(4,520 点 / 既定 6,000 点 → `▓▓▓▓▓▓▓░░░` = 7 つ)は四捨五入では 8 つになる。
**例を正**とし、`Math.floor(ratio × 10)` を採った(満タンは ratio = 1 のときだけ)。

### N-6. ホームの「はじめから」は `#/play?new=1`(§9.1)
§9.1 は「途中のゲームがあれば主ボタンは『続きから』、副に『はじめから』」とだけ定める。
両方とも同じゲーム画面へ行くので、破棄の意図をクエリで渡す形にした
(`#/play?new=1` のときだけ保存を捨て、[04](04-telemetry-and-metrics.md) §3 の
`game_end` / `reason=abandon` を送る)。デイリーは終了時に保存を消すので、`#/daily` に入り直せば新しい挑戦になる。

### N-7. 練習プレイという区別をやめた(§7.2、2026-09-21)
当初は「デイリーの初回だけが公式、2 回目以降は練習で統計にも記録にも入れない」としていた
(`isPractice`)。デイリーのランキングを**その日のベスト**に変えた(docs/08 §1)ため、
どの挑戦も公式になり、区別が要らなくなった。

- `stats`(ベストスコア・プレイ回数・連続日数)は**どの挑戦でも更新する**
- `daily:results` はその日のベストと挑戦回数を持つ
- テレメトリの `isPractice` 列は**残す**(意味は変えない。docs/04 §4)。常に 0 を送る
- `daily_result` イベントは **1 日 1 件のまま**(その日の初回の終了時だけ送る)。
  2 回目以降は `game_end` で数えられる

### N-8. epoch より前の日は通算番号を出さない(§9.4)
`dailyNumber()` は epoch(`config.daily.epoch` = 2026-10-01)より前の日に 0 以下を返す
(公開前のプレイや、端末時計が過去の場合。docs/06 §8「端末時計が過去」)。
共有テキストとゲーム画面のモード表示で「#-13」のような番号を見せないため、
**番号が 1 未満なら `#<n>` を省く**(`HAMARU Daily (2026-09-17)` / 「今日の挑戦」)。
テレメトリの `daily_result.dailyNo` には値をそのまま送る(docs/04 §10 N-2)。
epoch 自体は公開日の判断なので変えていない。
