# 01. ゲーム仕様書 — HAMARU

実装者向け。ここに書かれていない挙動は「もっとも単純な解釈」を採り、`docs/` に追記する。
数値はすべて `src/config/game-config.json` の**既定値**であり、改善ループが変更しうる。
ここでは `config.xxx` の形で参照する。

## 1. ルール(10 秒で説明できる形)

1. 盤は 10×10。下のトレイに 3 つのブロックが出る。
2. ブロックをドラッグして盤の空きに置く。回転はできない。
3. 縦か横の 1 列(10 マス)が埋まると消える。複数列同時なら高得点。
4. 3 つ全部置くと次の 3 つが出る。
5. トレイのどのブロックも置けなくなったら終了。

## 2. 盤と座標

- 盤: `Board` = 長さ 100 の `Uint8Array`。`board[y * 10 + x]`、`0` = 空、`1..6` = 色インデックス。
- 座標: 左上が `(0,0)`、右方向 `x+`、下方向 `y+`。
- 盤サイズは `config.board.size`(既定 10)。**v1 の UI は 10 固定**だが、core は N×N に対応させる(将来の 8×8 モード用)。

## 3. ピースカタログ

回転なし。各形状は固定の向きで別 ID として存在する(1010! 方式)。
形状は `src/core/shapes.ts` に **原点 (0,0) を含む相対座標の配列** で定義する。

| カテゴリ | ID | セル | 重み(既定) |
|---|---|---|---|
| 単体 | `dot` | (0,0) | 1.0 |
| 横線 | `h2` `h3` `h4` `h5` | 1×2 … 1×5 | 1.0 / 1.0 / 0.8 / 0.5 |
| 縦線 | `v2` `v3` `v4` `v5` | 2×1 … 5×1 | 同上 |
| 正方形 | `sq2` | 2×2 | 1.0 |
| 正方形 | `sq3` | 3×3 | 0.35 |
| 小 L(3 セル、2×2 から 1 欠け) | `c_ne` `c_nw` `c_se` `c_sw` | 例 `c_nw` = (0,0)(1,0)(0,1) | 各 0.7 |
| 大 L(5 セル、3×3 の L) | `L_ne` `L_nw` `L_se` `L_sw` | 例 `L_sw` = (0,0)(0,1)(0,2)(1,2)(2,2) | 各 0.45 |
| T(4 セル) | `t_n` `t_e` `t_s` `t_w` | 例 `t_s` = (0,0)(1,0)(2,0)(1,1) | 各 0.5 |
| 長方形 | `r2x3` `r3x2` | 2 行×3 列 / 3 行×2 列 | 各 0.4 |

合計 25 形状。**この表が形状の正**であり、実装時に `shapes.ts` からこの表を生成するテストを書く(`shapes.test.ts`: セル数・バウンディングボックス・ID の一意性・原点を含むこと)。

命名の向き: `c_nw` は「2×2 のうち北西(左上)に 3 セルが寄っている」= 欠けているのが南東。`L_sw` は「L の角が南西」。`t_s` は「T の突起が南(下)向き」。

### 色
ピース生成時に `1..6` の色インデックスを **形状カテゴリで固定**する(視認性のため同じ形は同じ色):
線=1、正方形=2、小L=3、大L=4、T=5、長方形=6、dot=1。色の実値は [03-design-system.md](03-design-system.md)。

## 4. 乱数とピース生成

### 4.1 乱数
- `createRng(seed: string)`: 文字列を `cyrb53` でハッシュし、`mulberry32` を初期化。`next()` は `[0,1)` の `number`。状態は `number` 1 つで、`GameState` に保存し**途中再開しても同じ列が続く**。
- エンドレスのシード: `endless:<installId>:<startedAtMs>`。
- デイリーのシード: `daily:<YYYY-MM-DD>`(**UTC** 日付。全世界共通)。

### 4.2 トレイ生成(`generateTray(rng, board, config)`)
1. `config.pieces.weights` に基づく重み付き抽選を 3 回。
2. `config.pieces.noTripleDuplicate`(既定 true)なら、3 つが同一 ID の場合は 3 つ目を引き直す(最大 10 回)。
3. `config.pieces.fitGuarantee`(既定 `"oneOfThree"`)なら、3 つのうち少なくとも 1 つが現在の盤に置ける組み合わせになるまで全体を引き直す(最大 20 回。超えたらそのまま返し、ゲームオーバー判定に任せる)。`"none"` なら保証しない。
4. `config.pieces.pity.enabled`(既定 true)かつ盤の埋まり率 ≥ `config.pieces.pity.threshold`(既定 0.6)なら、セル数 ≤ 3 の形状の重みを `config.pieces.pity.smallBoost`(既定 1.5)倍にする。

**デイリーモードでは 3 と 4 を強制 OFF**(`fitGuarantee: "none"`, `pity.enabled: false`)。盤の状態に依存しないため**全プレイヤーのピース列が完全に一致**する。これは公平性の要件であり、実験でも変更不可(`experiments.json` の `lockedInDaily` で保護)。

## 5. 配置と消去

### 5.1 配置可否 `canPlace(board, shape, x, y)`
形状の全セル `(x+dx, y+dy)` が盤内かつ空なら true。

### 5.2 配置 `place(state, trayIndex, x, y) → { state, result }`
1. `canPlace` が false なら `result.ok = false`、state は不変。
2. セルを埋める(色はピースの色)。
3. **完全に埋まった行・列を同時に検出**して全て消す(行と列の交差セルは 1 回だけ消える)。
4. スコア加算(§6)。
5. トレイのそのスロットを `null` に。3 スロットとも `null` なら新トレイを生成し `round += 1`。
6. **ゲームオーバー判定**: トレイに残る(null でない)ピースのうち、盤のどこかに置けるものが 1 つもなければ `status = "over"`。
7. `result` に `placedCells`, `clearedRows`, `clearedCols`, `clearedCells`, `scoreDelta`, `streakAfter`, `boardCleared`, `gameOver` を入れる(演出用)。

### 5.3 不変条件(テストで担保)
- 消去後に完全な行・列は存在しない。
- スコアは単調非減少。
- `place` は入力を変更しない(構造共有した新オブジェクトを返す)。

## 6. スコアリング

| 要素 | 式(既定) | config キー |
|---|---|---|
| 配置 | +セル数 | `scoring.perCell` = 1 |
| 消去 | `n` 列同時消しで `10 × n × (n+1) / 2` → 1:10, 2:30, 3:60, 4:100, 5:150, 6:210 | `scoring.lineBase` = 10 |
| ストリーク | 連続して消去が発生した配置回数 `s`。消去点に `min(1 + step×(s−1), max)` を乗算 | `scoring.streak.step` = 0.25, `scoring.streak.max` = 2.0 |
| 全消し | 消去後に盤が空なら +300 | `scoring.boardClearBonus` = 300 |

- ストリークは「消去がない配置」で 0 に戻る。トレイ更新では途切れない。
- 端数は各加算ごとに `Math.round`。
- 表示は 3 桁区切り。

## 7. モード

### 7.1 エンドレス(`mode: "endless"`)
- いつでも開始。終了時にベストスコアを更新。
- 途中終了(ホームに戻る)しても状態を保存し、次回「続きから」を出す。

### 7.2 デイリー(`mode: "daily"`)
- 1 日 1 題(UTC)。ホームのカードに「今日の挑戦」「残り時間」「達成状況」を表示。
- **何度でも挑戦でき、その日のベストが記録になる**(2026-09-21、docs/08 §1)。終了後は「もう一度挑戦」できる。
  ランキングに載るのもベスト。低い得点で終えても記録は下がらず、挑戦回数だけが増える。
- 途中再開可。ただし日付が変わったら破棄して新しい日に切り替える。
- 終了後の結果カード(§9.4)を共有できる。
- デイリー連続達成日数(`dailyStreak`)を保持。UTC で 1 日飛ぶと 0 に戻る。

### 7.3 将来(v1.1 候補、core は対応しておく)
- タイムアタック(`mode: "timed"`, 120 秒)、8×8 盤。

## 8. 操作

### 8.1 ポインタ(タッチ / マウス)
- トレイのピースを `pointerdown` で掴む。**タッチ時は指の `config.input.touchLiftOffset`(既定 70 px)上**にピースを持ち上げ、トレイ表示サイズ(セル 0.6 倍)から盤のセルサイズへ 120 ms で拡大する。マウス時はオフセット 0。
- ドラッグ中、ピースの**左上セルに最も近い盤セル**をスナップ先とし、置けるなら「ゴースト」(半透明)を表示。さらに**置いた場合に消える行・列をハイライト**する(`config.input.previewClears`、既定 true)。
- `pointerup`: 置けるなら配置。置けないならトレイへ 180 ms で戻る。
- `pointercancel` / 画面離脱はキャンセル扱い。
- 盤外へのドロップはキャンセル。
- スクロールを防ぐため盤とトレイに `touch-action: none`。

### 8.2 キーボード(アクセシビリティ要件)
- `1` `2` `3` でトレイ選択、矢印で盤上のカーソル移動(ピースの左上基準)、`Enter`/`Space` で配置、`Esc` で選択解除。
- 選択中はゴースト表示。置けない位置では `aria-live` で「置けません」は言わない(うるさいため)。配置成功と消去は `aria-live="polite"` で「12 点、1 列消去」の形で通知。

### 8.3 ハプティクス
- 配置成功で `navigator.vibrate(10)`、消去で `vibrate([10, 30, 20])`。設定で OFF 可(`settings.haptics`、既定 ON)。非対応環境では無視。

### 8.4 音(BGM・効果音)
- 遊んでいる画面(エンドレス / デイリー / レベル)でだけ鳴らす。**既定はどちらも OFF**(docs/00 §5)。
- 設定「BGM」(`settings.music`)と「効果音」(`settings.sfx`)で別々に、
  **ホームとゲーム画面の音符ボタン**で両方まとめて切り替えられる。
- 効果音が鳴るのは、置いた時・消えた時・全消し・レベルクリア・ゲームオーバー。
  連鎖が続くほど消える音が上がる。
- 音源ファイルは持たず、Web Audio で合成する。曲と実装は [10-audio.md](10-audio.md)。

## 9. 画面

ルーティングはハッシュ(`#/`, `#/play`, `#/daily`, `#/settings`, `#/about`)。単一 HTML。

### 9.1 ホーム(`#/`)
```
┌──────────────────────────────┐
│ HAMARU               ♪  ⚙︎   │
│                              │
│ ┌──────────────────────────┐ │
│ │ 今日の挑戦  9/17         │ │  ← デイリーカード(未挑戦/挑戦中/達成 + 残り時間)
│ │ [ 挑戦する ]   連続 4 日  │ │
│ └──────────────────────────┘ │

│                              │
│ ベスト 12,340   プレイ 58 回 │

```
- 途中のゲームがあれば主ボタンは「続きから」、副に「はじめから」。

### 9.2 ゲーム(`#/play`, `#/daily`)
```
┌──────────────────────────────┐
│ ←   スコア 1,240   ベスト 9k │
│            ×1.5(ストリーク)  │
│ ┌──────────────────────────┐ │
│ │      10×10 盤            │ │
│ │  (画面幅いっぱい、正方形) │ │
│ └──────────────────────────┘ │
│                              │

```
- 盤の一辺 = `min(画面幅 − 32px, 画面高 − ヘッダ − トレイ, 520px)`。
- ストリーク倍率は 1.0 のとき非表示。
- 一時停止はない(状態は常時保存されるので、離脱=一時停止)。

### 9.3 ゲームオーバー(オーバーレイ)
- 置けないことが確定したら 600 ms かけて**置けないピースを暗転**させてから表示。
- 内容: スコア、ベスト(更新時は「NEW BEST」)、消した列数、最長ストリーク、ラウンド数。
- ボタン: 「もう一度」(主)、「ホーム」。デイリーは「結果を共有」(主)、「ランキングを見る」、「もう一度挑戦」、「ホーム」。
  デイリーではその日のベストと挑戦回数(「今日のベスト 1,224(3 回目)」)も出す。

### 9.4 デイリー結果カード(共有テキスト)
```
HAMARU Daily #<n> (<YYYY-MM-DD>)
4,520 pts · 18 lines · streak x2.0
▓▓▓▓▓▓▓░░░
https://<host>/#/daily
```
- `#<n>` は 2026-10-01 を #1 とする通算番号(`config.daily.epoch`)。
- ゲージは `min(score / config.daily.shareGaugeMax, 1)` を 10 段階で表示(既定 6000)。
- `navigator.share` が使えれば共有シート、なければクリップボードにコピーし「コピーしました」をトースト表示。

### 9.5 設定(`#/settings`)
言語(自動 / 日本語 / English)、テーマ(自動 / ライト / ダーク)、ハプティクス、アニメーション軽減(OS 設定に従う / 常に軽減)、消去プレビュー、データの削除(確認ダイアログ付き)、バージョン、プライバシーへのリンク。

### 9.6 About / プライバシー(`#/about`)
何を送信しているか(§11)を平易に明記。「個人を特定する情報は送っていません」。

## 10. 永続化(localStorage)

キー接頭辞 `hamaru:v1:`。全て JSON。`schemaVersion` を持ち、読み込み時に `migrate()` を通す。壊れていれば該当キーだけ初期化(ゲーム全体を止めない)。

| キー | 内容 |
|---|---|
| `install` | `{ id: uuid, createdAt, firstVersion }` |
| `settings` | §9.5 の設定 |
| `stats` | `{ gamesPlayed, bestScore, totalLines, totalScore, longestStreak, dailyStreak, lastDailyDate }` |
| `game:endless` | 途中の `GameState`(なければ削除) |
| `game:daily` | 途中の `GameState` + `date` |
| `daily:results` | 直近 60 日分 `{ date: { score, lines, attempts } }`(score はその日のベスト) |
| `telemetry:queue` | 未送信イベント |
| `experiments` | 割り当てキャッシュ `{ expId: variant }` |

localStorage が使えない環境(プライベートモード等)では**メモリ内フォールバック**で動作し、保存できない旨は出さない。

## 13. エッジケースの仕様

| 状況 | 挙動 |
|---|---|
| 初手で 3 つとも置けない | `fitGuarantee` により通常起きない。起きた場合は即ゲームオーバー(テストで到達可能にする) |
| 行と列が同時に消え交差する | 交差セルは 1 回だけ数える。列数は行+列の合計(例 1 行 + 1 列 = 2 列 = 30 点) |
| 3×3 で 3 行 + 3 列同時 | 6 列 = 210 点 ×ストリーク |
| ドラッグ中にタブが非表示 | キャンセル。ピースはトレイへ |
| 日付が変わった瞬間にデイリーをプレイ中 | 進行中のゲームは続行できる。終了時の記録は**開始時の日付**に紐づける |
| localStorage の容量超過 | `telemetry:queue` を捨ててから再試行。それでも失敗なら黙って続行 |
| 画面回転 | 盤を再レイアウト。ドラッグ中ならキャンセル |
| 二本指 | 最初のポインタのみ扱う(`pointerId` 固定) |

## 14. 実装ノート(実装フェーズで解消した曖昧さ)

### N-1. 「原点 (0,0) を含む」= バウンディングボックス原点への正規化(§3)
§3 は形状を「原点 (0,0) を含む相対座標の配列」と定義し、§3 の注記は
`shapes.test.ts` で「原点を含むこと」を検査せよと書いている。
しかし §3 が同時に定める幾何(方位の命名)と両立しない形状がある。

| 形状 | セル | (0,0) を含むか |
|---|---|---|
| `c_se`(北西が欠ける) | (1,0)(0,1)(1,1) | ✗ |
| `L_se`(角が南東) | (2,0)(2,1)(0,2)(1,2)(2,2) | ✗ |
| `t_n`(突起が北) | (1,0)(0,1)(1,1)(2,1) | ✗ |
| `t_w`(突起が西) | (1,0)(0,1)(1,1)(1,2) | ✗ |

幾何(方位の命名と §3 の 3 つの例)を正とし、「原点を含む」は
**バウンディングボックスの原点に正規化されている = `min(dx) === 0` かつ `min(dy) === 0`**
の意味と解釈した。テストもこの条件を検査する。
配置 API(`canPlace(board, size, shape, x, y)`)は (x, y) を
**バウンディングボックスの左上**として扱う。§8.1 の「ピースの左上セル」もこの点を指す。

### N-2. 形状カテゴリは `shapes.ts` 内部に持つ(§3「色」)
色をカテゴリで固定するため、`ShapeCategory`(dot / line / square / smallL / bigL / tee / rect)を
`shapes.ts` に定義し、`CATEGORY_COLOR` から `Shape.color` を導出する。
`Shape` 型([02](02-architecture.md) §3 の契約)は変更していないので、
カテゴリは `SHAPE_CATEGORY` マップとして別途 export する。

### N-3. pity は「手順 1 で使う重み」を変える(§4.2)
§4.2 は pity を手順 4 に書いているが、pity は重み付き抽選そのものを変える設定なので、
実装では **最初に実効重みを求めてから手順 1〜3 を回す**。
(手順 4 を文字どおり最後に適用すると、既に引いたピースには効果がなく無意味になるため。)

### N-4. `fitGuarantee` はベストエフォート(§4.2)
§4.2 が定めるとおり、再抽選は最大 20 回で打ち切ってそのまま返す。
したがって「3 つのうち少なくとも 1 つ置ける」は**保証ではなく強い傾向**であり、
`dot` しか置けないような極端な盤では稀に保証が外れる(その場合は §5.2 手順 6 の
ゲームオーバー判定に委ねる)。単体テストもこの前提で書いている。

### N-5. 共有ゲージは切り捨て(§9.4)
§9.4 は「`min(score / shareGaugeMax, 1)` を 10 段階で表示」としか書いていないが、
同じ節の例(4,520 点 / 既定 6,000 点 → `▓▓▓▓▓▓▓░░░` = 7 つ)は四捨五入では 8 つになる。
**例を正**とし、`Math.floor(ratio × 10)` を採った(満タンは ratio = 1 のときだけ)。

### N-6. ホームの「はじめから」は `#/play?new=1`(§9.1)
§9.1 は「途中のゲームがあれば主ボタンは『続きから』、副に『はじめから』」とだけ定める。
両方とも同じゲーム画面へ行くので、破棄の意図をクエリで渡す形にした
(`#/play?new=1` のときだけ保存を捨て、[04](04-telemetry-and-metrics.md) §3 の
`game_end` / `reason=abandon` を送る)。デイリーは終了時に保存を消すので、`#/daily` に入り直せば新しい挑戦になる。

### N-7. 練習プレイという区別をやめた(§7.2、2026-09-21)
当初は「デイリーの初回だけが公式、2 回目以降は練習で統計にも記録にも入れない」としていた
(`isPractice`)。デイリーのランキングを**その日のベスト**に変えた(docs/08 §1)ため、
どの挑戦も公式になり、区別が要らなくなった。

- `stats`(ベストスコア・プレイ回数・連続日数)は**どの挑戦でも更新する**
- `daily:results` はその日のベストと挑戦回数を持つ
- テレメトリの `isPractice` 列は**残す**(意味は変えない。docs/04 §4)。常に 0 を送る
- `daily_result` イベントは **1 日 1 件のまま**(その日の初回の終了時だけ送る)。
  2 回目以降は `game_end` で数えられる

### N-8. epoch より前の日は通算番号を出さない(§9.4)
`dailyNumber()` は epoch(`config.daily.epoch` = 2026-10-01)より前の日に 0 以下を返す
(公開前のプレイや、端末時計が過去の場合。docs/06 §8「端末時計が過去」)。
共有テキストとゲーム画面のモード表示で「#-13」のような番号を見せないため、
**番号が 1 未満なら `#<n>` を省く**(`HAMARU Daily (2026-09-17)` / 「今日の挑戦」)。
テレメトリの `daily_result.dailyNo` には値をそのまま送る(docs/04 §10 N-2)。
epoch 自体は公開日の判断なので変えていない。
