# 00. プロジェクト概要 — HAMARU

> 「はまる」= ブロックがぴったり収まる / 夢中になる。両方の意味を名前にした。

## 1. 一言で言うと

**10×10 の盤にかけらを置き、縦横の列を揃えて消す**、誰でも 10 秒でルールが分かるパズル。
ただし供給に運がない——**次のかけらは、いま置いた場所のまわりの盤の形がそのまま出てくる**(「逆手」。docs/01 §1)。
公開後は **Claude(Opus 5)が毎日、実プレイデータを見て小さな改善を提案・検証・出荷し続ける**。
人間は「見守る・止める・方向を変える」だけでよい状態を目標にする。

## 2. なぜこのゲームか(2 案比較)

| 観点 | A. ブロックはめ込み(採用) | B. 日替わり単語パズル |
|---|---|---|
| 市場実績 | 1010! / Block Blast 系はカジュアルパズルで最大級の DAU | Wordle 系。強いが一極化 |
| 言語依存 | なし。世界中に配れる | 辞書が必要。言語ごとに作り直し |
| コンテンツ供給 | 盤から導出で無限。制作コストゼロ | 毎日の出題管理が要る |
| 自律改善との相性 | 出現確率・配点・救済ルールなど**数値パラメータが多く A/B しやすい** | 改善余地が UI に偏る |
| 1 セッションの長さ | 2〜10 分。指標が取りやすい | 1 日 1 回で頭打ち |

**採用理由(1 文):** 言語非依存でコンテンツ生成が不要、かつ改善対象のパラメータが豊富で「自律改善」の効果を数値で示せるから。

### 既存クローンとの差別化
1. **逆手(さかて)— 供給に運がない**(2026-09-24 に全面刷新)。次のかけらは盤から導かれ、
   乱数は開始盤にしか使わない。**自分で自分の次の手を作っている**のがこのゲームの正体で、
   「運が悪かった」という逃げ道が無い。だから負けるたびに原因が分かり、もう 1 回押す。
   同じ盤・同じ手順なら必ず同じ結果になるので、記録はサーバで再生して検証できる(docs/08)。
2. **デイリーチャレンジ**: 全員が同じ開始盤で競う。結果カードを共有できる(Wordle 型の口コミ導線)。
3. **広告ゼロ・登録ゼロ・1 秒起動**: PWA、初回ロード JS 60 KB(gzip)以内。
4. **「はまった」感触の作り込み**: 吸着・列消し演出(金継ぎライン)に予算を集中する。詳細は [03-design-system.md](03-design-system.md)。

## 3. 完了条件(このプロジェクトの Definition of Done)

### フェーズ 1: 設計(本書群) — 完了条件
- 実装者(Opus 5)が **質問なしで** 実装に着手できる粒度で、ルール・画面・データ・API・CI・改善ループが定義されている。

### フェーズ 2: 実装 v1.0 — 完了条件
- `https://<name>.<account>.workers.dev` でゲームが遊べる(エンドレス + デイリー)。
- `main` への push で自動デプロイ、PR で CI(型・Lint・単体・シミュレーション・E2E・サイズ予算)が走る。
- テレメトリが Analytics Engine に届き、`scripts/metrics` で KPI が取れる。

### フェーズ 3: 自律改善ループ稼働 — 完了条件
- 毎日 1 回、Claude が指標を読み、実験 or 改善 PR を作り、ゲートを通れば自動マージ→デプロイされる。
- 実験は事前登録された指標で自動判定(採用 / 却下 / 継続)される。
- 人間は週次ダイジェスト Issue を読むだけでプロダクトの状態を把握できる。
- 停止スイッチ(`KAIZEN_ENABLED=false`)で即時停止できる。

## 4. 北極星指標と KPI

**北極星: 週あたりの「プレイされたゲーム数」(games / week)**
※ 匿名インストール ID ベース。ログインなし。

| KPI | 定義 | v1 目標(公開 30 日後) |
|---|---|---|
| Games per session | game_end 数 / session_start 数 | ≥ 2.5 |
| Median session length | session の中央値 | ≥ 4 分 |
| D1 return | 初回 session の翌日に session がある install の割合 | ≥ 20 % |
| Daily completion | daily を開始した install のうち game_end した割合 | ≥ 70 % |
| Share rate | 共有ボタン押下 / daily game_end | ≥ 5 % |
| Crash-free | error イベントのない session の割合 | ≥ 99.5 % |
| LCP / INP(p75) | Web Vitals | ≤ 1.5 s / ≤ 100 ms |

指標の厳密な定義と SQL は [04-telemetry-and-metrics.md](04-telemetry-and-metrics.md)。

## 6. 主要技術判断(ADR 要約)

| # | 判断 | 理由 | 却下した案 |
|---|---|---|---|
| ADR-1 | Cloudflare **Workers + Static Assets** 単一 Worker | 静的配信と `/api/*` を 1 つの wrangler 設定で扱え、無料枠(10 万 req/日)で十分 | Pages(新規は Workers が推奨路線、Functions と設定が分かれる) |
| ADR-2 | フレームワークなし(Vite + TypeScript + DOM) | 依存が少なく AI が壊しにくい。100 セルの盤に仮想 DOM は不要。バンドル小 | React / Svelte(依存更新が自律ループのノイズになる) |
| ADR-3 | ゲームロジックは **純粋関数 + シード付き乱数** の `core/` に隔離 | 単体テスト・ヘッドレスシミュレーション・デイリー(同一シード)が全て同じコードで動く | UI と混在 |
| ADR-4 | テレメトリは **Workers Analytics Engine** | 無料 10 万点/日、保持 3 ヶ月、SQL API で集計、スキーマレス | D1(集計クエリが Worker 呼び出しを消費、リーダーボード時に導入) |
| ADR-5 | チューニング値は **`game-config.json` + `experiments.json`** に集約し zod で検証 | 改善エージェントの変更対象を「データ」に寄せ、コード改変を最小化 | コード内定数 |
| ADR-6 | 改善ループは **GitHub Actions cron + `anthropics/claude-code-action@v1`(Opus 5)** | ソース・CI・PR・監査ログが GitHub 内で完結。ゲートは既存 CI をそのまま使える | Managed Agents 定期デプロイ(Anthropic 側でホスト。GitHub 連携・Vault 設定が増える。将来の移行先として記録) |
| ADR-7 | 実験は **同時に 1 本**、判定は決定的スクリプト | LLM に統計判断をさせない。再現可能・説明可能 | 多腕バンディット(サンプル数が足りない) |
| ADR-8 | 自動マージは **変更クラスで制限**(config / UI / 文言 / CSS のみ) | Worker・ワークフロー・依存・プライバシーに触る PR は人間承認 | 全自動 |

## 8. 用語

| 用語 | 意味 |
|---|---|
| install | 匿名インストール ID(localStorage の UUID)で識別される端末+ブラウザ |
| session | 画面がアクティブになってから 30 分無操作までの単位 |
| game | game_start から game_end まで |
| 逆手(さかて) | 次のかけらを盤から導く本作の中核ルール(docs/01 §1・§5.3) |
| かけら(piece) | 手に持っている形。形状カタログは無く、毎手ちがう |
| 熱(heat) | 最後に列を消してからの手数。上がるほど次のかけらが大きくなる |
| 手持ち(hand) | 画面下のかけら置き場。**常に 1 個** |
| kaizen | 自律改善ループの総称。`kaizen/` ディレクトリがその記憶 |
| experiment | 事前登録された A/B テスト。`experiments.json` の 1 エントリ |
