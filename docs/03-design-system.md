# 03. デザインシステム — HAMARU

## 1. 方向性

**テーマ: 「釉薬(ゆうやく)のかかったタイルを、窯の中で並べる」**

このゲームの快感は「カチッと収まる」触覚にある。それを画面で表現するために、
かけらを**艶のある陶器タイル**、盤を**目地のある焼成トレイ**として描く。
列が消える瞬間は**金継ぎ**(割れ目に金が走る)を引用し、金色の線が走ってからタイルが砕けて消える。
これがこのゲームの「一つの記憶に残る要素(signature)」であり、演出予算はここに集中する。

避けるもの: 一般的なカジュアルゲームの「紺背景 + キャンディ色 + 丸ゴシック」。
本作は**深い墨緑の窯**に**低彩度で温かい釉薬色**を置く。派手さより「手触り」。

## 3. タイポグラフィ

| 役割 | 書体 | 理由 |
|---|---|---|
| 数値・見出し(スコア、ベスト、「NEW BEST」) | **Unbounded**(700 / 900、セルフホスト、数字と基本ラテンのみサブセット ≈ 25 KB) | 幅広で塊感のある字形がタイルと同じ「重さ」を持つ。数字が 1 桁ずつ「置かれた」ように見える |
| 本文 UI(ja / en) | システム UI スタック(`system-ui, -apple-system, "Hiragino Sans", "Noto Sans JP", sans-serif`) | 日本語 Web フォントは重い。UI 文言は短いので端末フォントで十分 |
| 補助ラベル・共有カード | 等幅(`ui-monospace, "SF Mono", Menlo, monospace`) | 共有テキストと画面を一致させる |

型スケール(`clamp` でモバイル→デスクトップ):
- `--fs-score`: `clamp(28px, 8vw, 44px)` Unbounded 900、`font-variant-numeric: tabular-nums`
- `--fs-title`: `clamp(24px, 6vw, 36px)` Unbounded 700、レタースペース `0.02em`
- `--fs-body`: `16px` / `--fs-small`: `13px`
- 行間 本文 1.5、見出し 1.1

スコアの変化は**数字ごとに 1 マス分下から滑り込む**(タイルが置かれる比喩)。`prefers-reduced-motion` では即時更新。

## 4. レイアウト

- 1 カラム、幅 `min(100vw, 560px)` を中央。左右余白 16px。
- 盤は正方形、一辺 = `min(100vw − 32px, 100dvh − ヘッダ 84px − 手持ち 132px − 余白 24px, 520px)`。
- 盤と手持ちの間 16px。手持ちは**スロット 1 つ + 熱**を中央に横並び(gap 18px)。
  スロットは `セル×0.7×最大 5` に収まり、最小でも `セル×3.4` の正方を占める
  (かけらの形が毎手変わるので、**枠の大きさは固定**して盤が動かないようにする)。
- 熱は 9px の点を `nextSize` 個。上限(6 個目 = `maxPiece` 到達)だけ `--kintsugi` にして、
  「これ以上は育たない / いま最も重い」ことを色で見せる。
- セル間の目地 = セルサイズの 8 %(丸め)。角丸はセルの 14 %。
- セーフエリア: `padding-bottom: env(safe-area-inset-bottom)`。
- 横長(landscape、高さ < 500px): 盤を左、手持ちを右に縦並び。

## 5. モーション

| 場面 | 仕様 | 時間 |
|---|---|---|
| 持ち上げ | 手持ち縮尺 0.7 → 1.0、影が大きくなる | 120 ms, ease-out |
| 吸着(はまる) | ドロップ位置から目標セルへ移動 + 1 フレームだけ 1.04 倍→1.0 の「沈み」 | 90 ms |
| 戻る | 手持ちへ戻る | 180 ms, ease-in-out |
| 金継ぎ消去 | ① 消える行/列に沿って金線が 1 方向へ走る(`--kintsugi`、`clip-path` アニメ)② 線通過後、各タイルが 40 ms ずつずれて縮小+フェード | ① 160 ms ② 160 ms(計 `fx.clearDurationMs` = 320) |
| 全消し | 盤全体が一瞬 `--kintsugi` の縁光り + 「全消し +300」ラベル | 500 ms |
| ゲームオーバー | 置けないかけらが `--danger` 縁取りで 600 ms かけて暗転 → オーバーレイがフェードイン | 600 + 200 ms |
| 消去プレビュー | 対象行列を `--kintsugi` 20 % で下塗り(点滅しない) | 即時 |

原則: **状態遷移は演出に依存しない**。演出はスキップ可能で、スキップしても最終 DOM は同じ。
`prefers-reduced-motion: reduce` または設定「軽減」では、移動系は 0 ms、消去はフェード 120 ms のみ。

## 8. アイコン・PWA

- アプリアイコン: `--kiln` 背景に 2×2 の釉薬タイル(柿・青磁・黄瀬戸・藤)を目地付きで配置。マスカブル対応(セーフゾーン 80 %)。
- `theme-color`: ダーク `#17262A` / ライト `#EEE9DF`(`media` 属性で切替)。
- スプラッシュは不要(起動 1 秒以内が目標)。

## 9. アクセシビリティ要件(CI で Lighthouse a11y ≥ 95)

- 盤は `role="grid"`、各セルは `role="gridcell"` + `aria-label="3行4列 空"`(カーソルが出ているときのみ読み上げ対象に)。
- 手持ちは `button` で `aria-label="2×3、4 マスのかけら"`、熱は `aria-label="次は 3 マス"`。
  形に名前が無いので、**寸法とマス数**で伝える。
- キーボード操作は [01 §8.2](01-game-spec.md)。
- コントラスト: 本文 ≥ 4.5:1、大きな数値 ≥ 3:1(両テーマで検証)。
- フォーカスリングを消さない。

## 10. 実装ノート(実装フェーズで解消した曖昧さ)

### N-1. 金継ぎ消去②のずれ幅は「予算内で等間隔」(§5)
§5 は「線通過後、各タイルが **40 ms ずつ**ずれて縮小 + フェード」を ② の 160 ms で行うと定めるが、
10 マスの行では 40 ms × 9 = 360 ms となり ② の予算を超える。
**合計時間(`fx.clearDurationMs` = 320 ms)を正**とし、ずれ幅は
`min(40 ms, ② の長さ ÷ (盤の一辺 − 1))`(既定の 10×10 では約 18 ms)とした。
遅延は `x + y` に比例させ、線が走る向きと同じ方向に砕けていくようにしている。

### N-2. 演出は「盤の上のレイヤ」で行う(§5 の原則)
「状態遷移は演出に依存しない」を物理的に保証するため、`place` の結果は**先に盤へ描き切り**、
消えたタイルは `.fxlayer` に置いた**複製**が砕ける。したがって演出を全部止めても DOM の最終形は同じで、
E2E(06 §5 `clear` / `reduced-motion`)は演出の完了を待たずに最終状態を検査できる。
吸着(沈み)だけは実セルに対する `transform` アニメーションだが、最終値は無変換なので同じ性質を持つ。

### N-3. Unbounded は可変フォント 1 ファイル(§3)
§3 は「700 / 900、セルフホスト、数字と基本ラテンのみサブセット ≈ 25 KB」と定める。
Google Fonts の CSS API に 700 と 900 を同時に要求すると**両方を含む可変フォント**が 1 本返るため、
`public/fonts/unbounded-var.woff2`(27.0 KB)を 1 ファイルだけ置き、
`@font-face` の `font-weight: 700 900` で受けている(静的 2 本 = 21.4 KB より 5.6 KB 大きいが、
リクエストが 1 本で済む)。予算 120 KB に対して 27.0 KB。

### N-4. 設定画面の「プライバシー」は行全体がリンク(§6)
§9.5 の一覧をそのまま行で並べると「プライバシー | プライバシー」と同じ語が 2 回出るため、
その行だけラベル + 山括弧の**リンク行**にした(コピーの重複を避ける。§7 の指針)。

### N-5. ホームのヒーローに釉薬 6 色の帯を置いた(§1)
§9.1 のワイヤは「HAMARU」と歯車だけだが、それだけでは本作の「釉薬」という主題が
最初の画面に出てこない。タイトル直下に 6 色の細い帯(高さ 6px)を 1 本だけ置き、
盤で使う色語彙を先に見せている。装飾はここだけに留め、他は設計書どおり。

### N-6. `theme-color` は 1 つのタグを JS で書き換える(§8)
§8 は「ダーク `#17262A` / ライト `#EEE9DF`(`media` 属性で切替)」と定めるが、
設定でテーマを**強制**できる(§9.5)ので、`media` 属性だけでは OS 設定に引きずられる。
`<meta name="theme-color">` を 1 つだけ置き、テーマ適用時に
`--kiln` の実効値(= どちらのテーマでも設計書どおりの値)を読み取って書き込む形にした。
OS のダーク/ライト切替にも `matchMedia` で追従する。

### N-8. 「このゲームについて」は、ホームの釉薬帯を縦にほどいた版面(§1、2026-09-22)
About は文章だけのページなので、演出予算(§5)は使わずに世界観を出す必要がある。
ホームのヒーローにある**釉薬 6 色の帯**(N-5)を 1 枚ずつに分け、節の頭に色見本(10px の角丸)として置いた。
節の区切りは 1px の細線に**金継ぎを 28px だけ**走らせる(割れた線を金で継いだ形)。

- 節のラテンの小見出し(ABOUT / MODES / MADE / KAIZEN / DATA / LICENCE)は等幅 11px・字間 0.14em。
  docs/03 §3 の「補助ラベルは等幅」に沿い、日本語の見出しは本文書体の 700 で受ける
- 見出しの書体を Unbounded にしないのは、サブセットがラテンと数字だけで日本語が落ちるため。
  Unbounded を使うのはワードマーク(HAMARU)だけ
- `.prose ul` の字下げが効いてしまうので、モードの一覧は `.about__body .about__list` で上書きする
  (クラスだけのセレクタでは負ける)

### N-7. ゲーム画面のヘッダは 84px の 1 行。画面はスクロールさせない(§4)
§4 の盤サイズの式は「ヘッダ 56px」を前提にしているが、[01](01-game-spec.md) §9.2 のワイヤの
ヘッダ(← / スコア / ベスト / ストリーク)はラベル + 大きな数字の 2 段なので実寸は 84px になる。
**式の意図(ヘッダと手持ちを引いた残りに正方形を収める)を正**とし、`--header-h: 84px` とした。
加えて `.screen.game` を `height: 100dvh; overflow: hidden` にして、
**ゲーム画面は絶対にスクロールしない**ことを保証している
(スクロールするとドラッグ座標と盤の位置がずれ、盤の下端や手持ちが画面外に出る)。
ホーム / 設定 / About のヘッダは従来どおり 56px。
