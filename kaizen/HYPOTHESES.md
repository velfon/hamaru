# HYPOTHESES — 仮説と根拠の台帳

書式: `## H-n: <仮説>` の下に 根拠 / 反証条件 / 関連実験。エージェントは新しい気づきをここに追記し、実験の結果で「支持 / 反証 / 不明」を更新する。

## H-1: 1 ゲームが 2〜5 分に収まると games_per_session が最大化する
- 根拠: 同ジャンルの一般的なセッション設計。短すぎると「運ゲー」感、長すぎると離脱。
- 反証条件: median_game_seconds を伸ばした実験で games_per_session が下がる。
- 状態: 不明(2026-W39 時点で観測値が 1 件も無い)

## H-2: デイリーは口コミの主経路になる(share → ref=share の session_start)
- 根拠: Wordle 型の結果カード。
- 反証条件: share_rate が 2 % 未満で推移、ref=share の install_new が 5 % 未満。
- 状態: 不明(2026-W39 時点で観測値が 1 件も無い)

## H-3: 終盤の「詰み」が早いと abandon_rate が上がる
- 根拠: 詰みを予感した時点で「はじめから」を押す行動。
- 反証条件: 詰みを遅らせる調整で abandon_rate が変わらない。
- 状態: 不明(2026-W39 時点で観測値が 1 件も無い)
- メモ: 2026-09-24 の逆手刷新で救済(pity)という仕組み自体が無くなった。詰みの速さを動かすノブは
  `sakate.growEvery`(かけらが大きくなる速さ)と `sakate.startTiles`(開始盤の密度)に置き換わる。

## H-4: 供給の運を消すと「もう 1 回」が増える(逆手の中心仮説)
- 根拠: 負けの原因が自分の 1 手に還るので「運が悪かった」で終われない(docs/00 §2)。
- 反証条件: 刷新後の games_per_session と D1 return が刷新前と変わらない、または下がる。
- 状態: 不明。刷新前後どちらの観測値も無いため、**この仮説は現状の設計では検証できない**
  (刷新は 2026-09-24 に一括で入っており A/B になっていない)。実データが出たあとも
  前後比較しか取れない点を、判断時に割り引く。
